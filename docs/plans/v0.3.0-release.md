# v0.3.0 — release the verify command, portable arguments, opencode install

Status: In progress — implementation, then review by `codex:sol`.

## The question

The uncommitted `/verify` work is good but unreleased, the shipped commands carry
an argument syntax that only one of the four harnesses understands, and the
guide does not tell an opencode user how to install anything. What is the
smallest release that fixes all three without redesigning the loop?

## Evidence inspected

- `commands/verify.md` (untracked) — frontmatter uses `${@:-the work just
  completed}`; `commands/delegate.md:5` uses `${@:-the task described above}`.
  pi expands `$@`, `$ARGUMENTS`, `$1`, and `${N:-default}`; Claude Code expands
  `$ARGUMENTS` and `$1`; opencode documents `$ARGUMENTS`. So `${@:-}` reaches
  Claude Code and opencode as a literal string.
- `.claude-plugin/plugin.json` (modified) already lists `./commands/verify.md`;
  `package.json` points `pi.prompts` at `./commands`, so pi picks the file up
  with no manifest change, and opencode reads `commands/*.md` by symlink.
- All four manifests read `0.2.0`; the tag `v0.2.0` is what pi, Claude Code, and
  Codex have installed.
- `/verify` passed nothing yet: no plan in any repository carries both
  `## Result` and `## Review`, so the loop itself is unproven.

## Working assumptions

- `$ARGUMENTS` is the only argument placeholder all four harnesses expand, and
  a command that receives an empty argument should say so rather than invent
  one.
- The opencode install is a symlink, because opencode has no package manager for
  skills or commands; the dev checkout is the source it links to.
- A version bump is required for pi, Claude Code, and Codex to see any of this,
  because each pins a ref.

## Rejected paths

- Teaching each command four syntaxes, or writing a wrapper that pre-expands
  arguments. Two placeholders in two files is smaller than a compatibility layer.
- Shipping the vault hooks (`vault-loop.ts`, `vault-loop.js`) inside the package
  in this release. They are host configuration rather than vault workflow, and
  moving them would mean removing the installed copies to avoid double
  injection. Left local, recorded in [[Agent Tooling]].
- A `0.3.1` that only carries `/verify`. The argument bug affects shipped files,
  so fixing it belongs in the same release.

## Steps

1. Replace `${@:-…}` with `$ARGUMENTS` in `commands/delegate.md` and
   `commands/verify.md`, and state what to do when it is empty.
   *Acceptance:* `grep -rn '\$@\|${@' commands/` returns nothing.
2. Adopt the sibling work: `/verify` in `commands/`, in the Claude manifest, in
   the README command table, and in the plan-file skeleton as `## Verified`.
   *Acceptance:* `claude plugin validate . --strict` passes and the README
   command table lists four commands.
3. Document the opencode install (skill and command symlinks) and correct the
   "three commands" and `v0.2.0` references.
   *Acceptance:* the README install block covers four harnesses; no `v0.2.0`
   reference survives outside the changelog-free history.
4. Bump all four manifests to `0.3.0`.
   *Acceptance:* a single grep shows four `0.3.0` and no `0.2.0`.
5. Verify independently, append `## Verified`, then hand Codex Sol the shas.
   *Acceptance:* every check in `## Verified` was rerun against the final tree,
   and remaining gaps are named.
